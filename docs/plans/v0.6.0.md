# v0.6.0 plan — flag-handling consolidation + wrapper module split

**Status:** signoff pending — user agreed to scope 2026-05-18; lock decisions block below.
**Author:** session 2026-05-18
**Scope philosophy:** `unwrapCall` is the headline lens the README and CLAUDE.md push (`parse → findCalls → unwrapCall → switch (u.kind)`). For `wrapped` calls, today it leaks: consumers must fall through to `resolveFlags(u.raw)` or `tokenAfter(u.raw, …)` (wrong target — `u.raw` is the OUTER call) to answer half the questions a security rule asks. This release makes `unwrapCall` complete — no fall-through needed for the common command-rule patterns.

The release also splits `src/semantic.ts` (396 lines, three internal sections) into a `src/wrappers/` module so feature changes land in localized files and future wrapper variants (deferred `unwrapDeep`, etc.) get a natural home.

Closes [#9](https://github.com/Questi0nM4rk/shell-ast/issues/9).

## What this release ships

`src/semantic.ts` → `src/wrappers/` directory, four files + a back-compat barrel:

| New file | Contents (extracted from semantic.ts) |
|---|---|

| `src/wrappers/index.ts` | Barrel re-exports |

`src/index.ts` continues to re-export from `./semantic.js` (no change to public top-level exports). All 245 existing TS tests stay green through the split — pure mechanical refactor before any behavior changes.

### Phase 1 — feature changes

1. **`flagValues` on `UnwrappedCall.plain` / `.wrapped`** — values for value-taking flags, threaded through from the resolver. Inner-call's `flagValues` on `wrapped`.
2. **`innerRaw: CallExprNode` on `UnwrappedCall.wrapped`** — the synthetic inner call already constructed in `unwrapCall` (currently discarded). Lets every query helper compose against the inner call uniformly.
3. **Query-helper polymorphism** — `tokenAfter` / `tokensAfter` / `hasFlag` / `indexOfFlag` / `tokenAt` / `flagsMatching` / `resolvedCmd` accept `CallExprNode | UnwrappedCall`. For `UnwrappedCall.wrapped` they dispatch to `innerRaw`; for `plain` to `raw`; for `wrapped-script` / `wrapped-opaque` to `raw` (the wrapper's own call — documented as wrapper-side semantics for those variants).
4. **IDEOLOGY §11 added** — "primary lens completeness." Becomes the principle future feature requests get filtered against.

After Phase 1, the canonical pattern collapses to:

```ts
const u = unwrapCall(call);
if (!u) return;
switch (u.kind) {
  case "plain":
  case "wrapped":
    if (u.cmd === "gcc" && /^\/(etc|usr|boot)/.test(u.flagValues["-o"]?.[0] ?? ""))
      deny("gcc -o targets system file");
    if (u.cmd === "git" && hasFlag(u, "--force")) deny("git --force");
    break;
  case "wrapped-script":
    // recurse into u.script (or u.innerAst via unwrapCallParsed)
    break;
  case "wrapped-opaque":
    if (u.wrapper === "sudo") warn("dynamic inner under sudo");
    break;
}
```

No more `u.raw` vs `u.innerRaw` decisions at the consumer; no re-running `resolveFlags`; no `tokensAfter(u.raw, …)` wrong-target footgun for sudo-wrapped commands.

### Phase 2 — test surface additions

`tests/_assertions.ts::testCmd` already exists and handles the four `UnwrappedCall` variants. Phase 2 extends it for the new fields:

1. **`ExpectedCmd.flagValues?: Record<string, ResolvedArg[]>`** — assert flagValues shape.
2. **`ExpectedCmd.innerRaw?: { cmdLit?: string; flagsLit?: string[] }`** — presence-only shape assertion. Avoids forcing test fixtures to spell out full AST node objects.
3. **Snapshot regression on `UnwrappedCall` shape** — new `tests/wrapper-shapes.test.ts` enumerates canonical invocations (sudo+rm, doas+gcc, bash+script, eval+positional, run0+kubectl-with-context, …) and snapshot-asserts the full `UnwrappedCall` JSON. Future variant additions surface in the snapshot diff so changes can't be silent.

No new test files for the existing variants — Phase 1's test additions land in existing files (or new feature-scoped files like `tests/unwrap-flagvalues.test.ts` and `tests/query-on-unwrapped.test.ts`).

## What this release explicitly does NOT ship

- **`wrapperFlagValues` on `wrapped-script` / `wrapped-opaque`** — no consumer asks for the wrapper's own value-flags as a security signal. Speculative API surface today.
- **Config-blind `flagValues` for unlisted tools** — would silently shift positionals (BUG-000 class in reverse). v0.5.0 plan §line-25 explicitly rejects heuristic flag inference. Stays opt-in via `globalFlags`.
- **`unwrapDeep` for chained wrappers** — still deferred. hook-kit's `recurseInlineShells` covers `sudo bash -c "rm"` by parsing the inner script.
- **A combined `u.valueOf(flag)` convenience** — would ship semantics. Consumer composes from primitives instead.
- **`wrapperRaw` field** — `u.raw` is already the outer call for `wrapped`. The naming asymmetry (`raw` vs `innerRaw`) is intentional: `raw` = "what the user typed," `innerRaw` = "what the wrapper was wrapping."
- **Pre-built test-case table `tests/_cases.ts`** — re-evaluated and rejected. Each test file scoping its own fixtures via `testCmd` is already low-boilerplate. Premature centralization.
- **Splitting `src/extract.ts`, `src/effects.ts`, `src/flags.ts`** — each is already focused and under 400 lines. No structural pain.

## Primary-lens principle (proposed addition to IDEOLOGY §11)

> **The primary lens must be complete.** When a release ships an opinionated "headline API" (the path the README and CLAUDE.md push), the consumer must never need to fall through to lower-level primitives to answer questions the headline API was designed for. Falling through to `.raw` (or re-running an upstream resolver) is the escape hatch for *uncommon* questions — not for the questions the primary lens claims to answer.
>
> Concretely: if the headline path is `unwrapCall` and security rules naturally want to ask "what value did flag X get on the inner command?", the answer must be reachable from the `UnwrappedCall` shape without re-synthesizing the inner call.
>
> This is downstream of §3 ("80/20 with escape hatches"): escape hatches are for the 20%, not for filling holes in the 80%.

This principle is what failed in v0.5.0 — `flagValues` landed on `ResolvedCall` (the secondary lens) but not on `UnwrappedCall` (the primary). The fix is bigger than one field because it's a class of "the inner call's information is unreachable from the primary lens."

## API: `UnwrappedCall` shape changes

### `plain` variant

```diff
  | {
      kind: "plain";
      cmd: string;
      flags: string[];
      args: ResolvedArg[];
+     flagValues: Record<string, ResolvedArg[]>;
      raw: CallExprNode;
    }
```

Populated from `resolved.flagValues` (the resolver already built it).

### `wrapped` variant

```diff
  | {
      kind: "wrapped";
      wrapper: string;
      cmd: string;
      flags: string[];
      args: ResolvedArg[];
+     flagValues: Record<string, ResolvedArg[]>;   // INNER call's flagValues
+     innerRaw: CallExprNode;                       // INNER synthetic CallExpr
      raw: CallExprNode;                             // OUTER call (unchanged)
    }
```

`innerRaw` is the synthetic call constructed from `rawArgs.slice(i)` (currently at `semantic.ts:302-308`, post-split at `src/wrappers/unwrap.ts`). Today used to drive `resolveFlags` then dropped; we surface the reference. `flagValues` is `innerResolved.flagValues`.

### `wrapped-script` / `wrapped-opaque` — unchanged

These variants have no inner `CallExprNode` to surface. Wrapper-side `flagValues` deferred per the explicit-NOT-ship list.

## API: query-helper polymorphism

Each helper in `src/query.ts` accepts a union:

```diff
- export function tokenAfter(call: CallExprNode, flag: string): ResolvedArg | undefined;
+ export function tokenAfter(target: CallExprNode | UnwrappedCall, flag: string): ResolvedArg | undefined;
```

Dispatch rule (single private helper):

```ts
function callOf(target: CallExprNode | UnwrappedCall): CallExprNode {
  if ("kind" in target) {
    return target.kind === "wrapped" ? target.innerRaw : target.raw;
  }
  return target;
}
```

Applies to all seven query helpers. For `wrapped-script` / `wrapped-opaque`: dispatches to `target.raw` (the wrapper's own call). Documented in JSDoc: "for script and opaque variants, queries the wrapper's call — recurse into the inner script via `unwrapCallParsed` for inner-call queries."

### Why not require explicit `.innerRaw` everywhere?

Considered. Rejected because:

1. **Headline simplicity.** `tokenAfter(u, "-o")` reads more naturally than `tokenAfter(u.kind === "wrapped" ? u.innerRaw : u.raw, "-o")` — the latter is exactly the kind of consumer-side switching the primary-lens principle is trying to eliminate.
2. **Type system carries the contract.** `UnwrappedCall` is an exhaustive union; `kind` discriminator is statically checked. The dispatch helper is six lines, fully typed.
3. **Escape hatch still available.** Consumers who want the wrapper's flags on a wrapped call use `tokenAfter(u.raw, "-u")` — explicit, no surprise.

## Test plan

### Snapshot table (Phase 2, `tests/wrapper-shapes.test.ts`)

Enumerate one canonical invocation per `UnwrappedCall` variant × wrapper category. Snapshot-assert the full shape. Any future change to `UnwrappedCall` surfaces here.

```ts
const cases = [
  { src: "rm -rf /tmp/x",                expectKind: "plain" },
  { src: "/usr/bin/git status",          expectKind: "plain" },           // basename + plain
  { src: "sudo rm -rf /tmp/x",           expectKind: "wrapped" },
  { src: "doas -u root rm /tmp/x",       expectKind: "wrapped" },
  { src: "sudo git -C /tmp worktree add", expectKind: "wrapped" },        // inner global-flag
  { src: 'bash -c "rm -rf /"',           expectKind: "wrapped-script" },
  { src: "eval 'rm /tmp/x'",             expectKind: "wrapped-script" },  // commandFromArgs
  { src: "sudo $CMD",                    expectKind: "wrapped-opaque" },  // dynamic inner
  { src: 'bash -c $SCRIPT',              expectKind: "wrapped-opaque" },  // dynamic script
  { src: "bash --version",               expectKind: "plain" },           // wrapper-named, no inner
];
```

Each case snapshots the full `UnwrappedCall` JSON (with `raw` / `innerRaw` stripped to `{type, args.length}` to keep snapshots readable).

### Feature tests (Phase 1)

`tests/unwrap-flagvalues.test.ts` — flagValues threading:

```ts
// plain
testCmd("git -C /tmp worktree add", {
  cmd: "git", flagValues: { "-C": ["/tmp"] }, args: ["worktree", "add"],
});

// wrapped — inner-call semantics
testCmd("sudo git -C /tmp worktree add", {
  wrapper: "sudo", cmd: "git", flagValues: { "-C": ["/tmp"] },
});

// gcc not in GLOBAL_VALUE_FLAGS table — empty flagValues
testCmd("gcc -o /tmp/x src.c", { cmd: "gcc", flagValues: {} });

// with opts.globalFlags — needs new testCmd opts field OR direct unwrapCall call
test("gcc -o with globalFlags opt", async () => {
  const ast = await parse("gcc -o /tmp/x src.c");
  const u = unwrapCall(findCalls(ast)[0]!, { globalFlags: { gcc: ["-o"] } });
  expect(u?.flagValues).toEqual({ "-o": ["/tmp/x"] });
});

// wrapped + opts threaded
test("sudo gcc -o with globalFlags opt", async () => {
  const ast = await parse("sudo gcc -o /tmp/x src.c");
  const u = unwrapCall(findCalls(ast)[0]!, { globalFlags: { gcc: ["-o"] } });
  expect(u?.kind).toBe("wrapped");
  expect(u?.flagValues).toEqual({ "-o": ["/tmp/x"] });
});

// innerRaw is the synthetic inner CallExpr
test("wrapped exposes innerRaw matching the inner cmd", async () => {
  const ast = await parse("sudo git -C /tmp worktree add");
  const u = unwrapCall(findCalls(ast)[0]!);
  expect(u?.kind).toBe("wrapped");
  if (u?.kind !== "wrapped") return;
  expect(u.innerRaw.type).toBe("CallExpr");
  expect(wordToLit(u.innerRaw.args[0]!)).toBe("git");
});
```

`tests/query-on-unwrapped.test.ts` — polymorphic helpers:

```ts
test("tokenAfter dispatches to innerRaw for wrapped", async () => {
  const ast = await parse("sudo gcc -o /tmp/x src.c");
  const u = unwrapCall(findCalls(ast)[0]!);
  expect(tokenAfter(u!, "-o")).toBe("/tmp/x");
});

test("hasFlag dispatches to innerRaw — sudo's flag NOT visible", async () => {
  const ast = await parse("sudo -u root gcc -o /tmp/x src.c");
  const u = unwrapCall(findCalls(ast)[0]!);
  expect(hasFlag(u!, "-o")).toBe(true);   // inner gcc has -o

test("wrapped-script dispatches to wrapper's raw", async () => {
  const ast = await parse('bash -c "gcc -o /tmp/x src.c"');

  expect(u?.kind).toBe("wrapped-script");
  expect(hasFlag(u!, "-c")).toBe(true);   // bash's -c
});

test("resolvedCmd on wrapped returns inner cmd basename", async () => {
  const ast = await parse("sudo /usr/bin/git status");
  const u = unwrapCall(findCalls(ast)[0]!);
  expect(resolvedCmd(u!)).toBe("git");
```

## Locked decisions

Awaiting sign-off. Lock at signoff with date below.

1. **`UnwrappedCall.wrapped.innerRaw` is non-optional.** Always populated for `wrapped`. Optional would force consumers to handle `undefined` for a value that exists by construction.
2. **`flagValues` non-optional on `plain` / `wrapped`** — always present, possibly empty `{}`. Matches `ResolvedCall.flagValues` semantics.
3. **Query helpers dispatch to `innerRaw` for `wrapped`, `raw` for everything else.** Wrapper-side queries explicit via `tokenAfter(u.raw, …)`.
4. **`wrapped-script` / `wrapped-opaque` query-helper behavior:** dispatch to `raw` (wrapper's call). For inner queries on `wrapped-script`, consumer parses `u.script` (or uses `unwrapCallParsed` for `innerAst`). For `wrapped-opaque`, inner is unreachable by definition.
5. **IDEOLOGY §11 added in this release.** Becomes the principle future feature requests get filtered against.
6. **`src/semantic.ts` becomes a back-compat barrel** re-exporting from `src/wrappers/index.js`. Existing consumer imports (`from "@questi0nm4rk/shell-ast/semantic"` IF anyone did that — the public surface is `@questi0nm4rk/shell-ast` only) continue to work.
7. **`tests/semantic.test.ts` renames to `tests/wrappers.test.ts`.** Internal rename only.
8. **No `tests/_cases.ts`.** Each test file scoping its own fixtures via `testCmd` is already low-boilerplate.

## Semver justification

0.6.0 (minor), not 0.5.2 (patch), not 1.0.0 (major):

- **Not patch:** structural API expansion (new fields on a typed union, new overloads on every query helper, internal directory restructure). Patch implies bugfixes only.
- **Not major:** pure additive. Existing consumers of `UnwrappedCall.plain` / `.wrapped` ignore the new fields; existing callsites of query helpers (which pass `CallExprNode`) still work — the overload accepts both. The src/semantic.ts → src/wrappers/ refactor is back-compat via the barrel re-export.
- **Is minor:** new public API surface, new internal structure, but no breaking change. Headline is "unwrapCall is now the complete primary lens" — feature framing, not bugfix.

Migration: hook-kit 0.6.0 picks up the new fields when bumping `shell-ast` to `^0.6.0`. No code changes required for consumers not using `flagValues` / `innerRaw` / polymorphic helpers — those are opt-in surface.
