# v0.5.0 plan — query primitives + flag-value preservation

**Status:** draft, awaiting sign-off
**Author:** session 2026-05-15/16
**Scope philosophy:** shell-ast is a **toolkit**. Per-tool knowledge ("gcc -o writes a file") lives in hook-kit. shell-ast provides primitives that let hook-kit ask the AST whatever it wants, without shell-ast pretending to know what every flag means.

---

## What this release ships

1. **`src/query.ts`** — zero-config query helpers operating on raw `CallExprNode`s.
2. **`flagValues` on `ResolvedCall`** — preserved values for consumed value-flags.
3. **Pluggable `globalFlags`** option on `resolveFlags(call, opts?)`.
4. **Basename match** in the `globalFlags` lookup — closes the `/usr/bin/git` gap.
5. **`findRedirects(ast, {depth: "top"})`** — parity with `findCalls`.
6. **README recipe**: "writing per-command rules" with both imperative and native-chain examples.

## What this release explicitly does NOT ship

- **Per-tool schemas** for gcc / git / docker / etc. — hook-kit's job.
- **`Role` vocabulary** (`fs-read`, `fs-write`, `fs-cwd`, …) — not shell-ast's vocabulary.
- **Schema registry / subcommand-chain matcher** — hook-kit's job.
- **Fluent `Query<T>` chain API** — native `Array.prototype` and Iterator Helpers cover the chain case; we don't need to reinvent them. If a real pain point emerges in hook-kit, a tiny wrapper can come later.
- **`unwrapDeep`** for chained wrappers — still deferred (v0.6.0+). `unwrapCallParsed` + `findCalls` cover this manually.
- **Heuristic flag inference** ("guess that `-o` takes a value because the next arg doesn't start with `-`") — too unreliable; silent failure mode is worse than a known gap.

## API: query helpers (new file `src/query.ts`)

All helpers take a `CallExprNode` and return either a scalar (`ResolvedArg | undefined | boolean | number`) or `ResolvedArg[]`. None of them require pre-calling `resolveFlags`. None of them require configuration.

### `tokenAfter(call, flag) → ResolvedArg | undefined`

Returns the token immediately following `flag` in `call.args` (raw AST order).

- For the `--flag=value` form: returns `value` (the part after `=`). Rationale: when a user asks "value of `--flag`", they mean either space-form or `=`-form; the AST shape is an implementation detail.
- For literal token mismatch (`-r` looking inside `-rf`): returns `undefined`. Rationale: avoid ambiguity. `hasFlag(call, "-r")` is the right helper for "is this short flag present in any form."
- For `flag` appearing at the end with no following token: returns `undefined`.
- For dynamic values: returns `DYNAMIC` (consumer can choose to deny-by-default or inspect `wordToParts`).

```ts
tokenAfter(parse("git --git-dir=/repo status").stmts[0].cmd!, "--git-dir");  // "/repo"
tokenAfter(parse("git -C /tmp worktree").stmts[0].cmd!, "-C");                // "/tmp"
tokenAfter(parse('git -C "$DIR" status').stmts[0].cmd!, "-C");                // DYNAMIC
tokenAfter(parse("git -C").stmts[0].cmd!, "-C");                              // undefined
tokenAfter(parse("gcc -rf out.txt").stmts[0].cmd!, "-r");                     // undefined (literal match)
```

### `tokensAfter(call, flag) → ResolvedArg[]`

Returns the value following EVERY occurrence of `flag` — one entry per occurrence. Same matching rules as `tokenAfter` (literal token + `=` form). Zero-config equivalent of `flagValues[flag]` when you don't want to pass `globalFlags`.

```ts
tokensAfter(parse("git -c k1=v1 -c k2=v2 status").stmts[0].cmd!, "-c");
// ["k1=v1", "k2=v2"]
```

For "give me the next N tokens after a single occurrence" (subcommand-positional case), compose `indexOfFlag` + `tokenAt`:

```ts
const idx = indexOfFlag(parse("git push origin main").stmts[0].cmd!, "push");
// idx === 1 (0 is "push", 1 is "origin", 2 is "main")
const remote = tokenAt(call, idx! + 1);  // "origin"
const branch = tokenAt(call, idx! + 2);  // "main"
```

### `hasFlag(call, flag) → boolean`

True if `flag` appears in `call.args` either as a literal token, as part of a combined short flag (`-r` is "present" in `-rf`), or as the LHS of an `=` form (`--git-dir` is "present" in `--git-dir=/repo`).

```ts
hasFlag(parse("gcc -rf out").stmts[0].cmd!, "-r");           // true
hasFlag(parse("git --git-dir=/r push").stmts[0].cmd!, "--git-dir");  // true
```

Rationale for the broader semantics: this is the "does the user's command use this option, in any syntactic form?" question. Strict-literal `hasFlag` would surprise consumers.

### `indexOfFlag(call, flag) → number | undefined`

Index of `flag` in `call.args` (1-indexed of all args, so first positional after cmd is index 0). Uses the same matching rules as `hasFlag`. Returns the index of the *containing* token for combined-short or `=` form (e.g. `-rf` is at the same index for both `-r` and `-f`).

### `tokenAt(call, i) → ResolvedArg | undefined`

`call.args[i]` resolved via `wordToLit`, returning `DYNAMIC` for non-static words. Undefined if `i` is out of range. The raw `call.args` is `Word[]` (the command itself is `args[0]`, so `tokenAt(call, 0)` is the cmd; this matches the underlying AST shape).

### `flagsMatching(call, predicate) → string[]`

Filter helper for flag tokens — returns the literal flag tokens that pass `predicate`. Useful for `of=...` style (`flagsMatching(call, f => f.startsWith("of="))`), pattern matching, etc.

```ts
flagsMatching(parse("dd if=/dev/zero of=/tmp/x bs=1M").stmts[0].cmd!, f => f.includes("="));
// ["if=/dev/zero", "of=/tmp/x", "bs=1M"]
```

### `resolvedCmd(call) → string | undefined`

Convenience: `wordToLit(call.args[0])`, plus basename strip if it contains `/`. Returns `undefined` for dynamic command words. Matches the lookup rule used by `globalFlags`.

```ts
resolvedCmd(parse("/usr/bin/git push").stmts[0].cmd!);  // "git"
resolvedCmd(parse("$CMD push").stmts[0].cmd!);          // undefined
```

## API change: `ResolvedCall` gains `flagValues`

```ts
export interface ResolvedCall {
  cmd: string;
  flags: string[];
  flagValues: Record<string, ResolvedArg[]>;   // NEW
  args: ResolvedArg[];
  raw: CallExprNode;
}
```

`flagValues` is populated only for flags that `resolveFlags` recognized as value-taking (from the built-in `GLOBAL_VALUE_FLAGS` table or any consumer-provided `globalFlags` option). Both the space form and `=` form populate it.

```ts
const r = resolveFlags(parse("git -c k1=v1 -C /tmp -c k2=v2 status").stmts[0].cmd!);
// r.flagValues = { "-c": ["k1=v1", "k2=v2"], "-C": ["/tmp"] }
// r.flags      = ["-c", "-C", "-c"]
// r.args       = ["status"]
```

Same flag appearing multiple times appends to the array. Dynamic values appear as `DYNAMIC`.

**This is purely additive** — existing consumers of `ResolvedCall` ignore the new field. No migration required.

## API change: `resolveFlags(call, opts?)` accepts options

```ts
export interface ResolveFlagsOptions {
  /** Additional value-taking flags per tool, merged on top of the
   *  built-in GLOBAL_VALUE_FLAGS table. Tool name is matched against
   *  `resolvedCmd(call)` (basename, if path-shaped).
   *
   *  Example: `{ terraform: ["-chdir", "-state"] }` makes
   *  `terraform -chdir=/tf apply` resolve with `-chdir=/tf` as a
   *  value-flag instead of leaking `/tf` into args. */
  globalFlags?: Record<string, readonly string[]>;
}

export function resolveFlags(
  call: CallExprNode,
  opts?: ResolveFlagsOptions
): ResolvedCall | null;
```

Built-in table is merged with consumer additions per call. No mutation of module-level state; safe to call concurrently with different options.

**Wrapper inheritance:** `unwrapCall` will need to thread `opts` through to its internal `resolveFlags` invocations on the inner call. Same shape:

```ts
export function unwrapCall(
  call: CallExprNode,
  opts?: ResolveFlagsOptions
): UnwrappedCall | null;
```

Same for `unwrapCallParsed`.

## API change: basename match in the lookup

Today: `firstLit === "git"` looks up `GLOBAL_VALUE_FLAGS.git`. `firstLit === "/usr/bin/git"` does not.

Change: when `firstLit` contains `/`, strip to basename for the table lookup only. The `cmd` field on `ResolvedCall` still preserves the original (`"/usr/bin/git"`).

```ts
resolveFlags(parse("/usr/bin/git -C /tmp worktree add").stmts[0].cmd!)
// → { cmd: "/usr/bin/git", flags: ["-C"], flagValues: { "-C": ["/tmp"] },
//     args: ["worktree", "add"], raw: ... }
```

Consumer-visible: `resolvedCmd(call)` returns the basename (already proposed above), so per-tool dispatch uses the same name regardless of path form.

## API change: `findRedirects(ast, {depth})`

```ts
export interface ExtractRedirectOptions {
  ops?: "all" | "write" | "read";   // existing
  depth?: "any" | "top";             // NEW — mirror findCalls
```

`depth: "top"` skips `CmdSubst`, `ProcSubst`, `BraceExp` subtrees, same as `findCalls`.

## Worked examples (will go in README)

### Example 1 — your gcc-output rule, hook-kit-style

```ts
// hook-kit rule
import { findCalls, resolvedCmd, tokenAfter } from "@questi0nm4rk/shell-ast";

function checkGccOutput(ast: ShellFile): string | null {
  for (const call of findCalls(ast)) {
    if (resolvedCmd(call) !== "gcc") continue;
    const out = tokenAfter(call, "-o");
    if (typeof out === "string" && !out.startsWith("/tmp/"))
      return `gcc -o ${out} writes outside /tmp`;
  }
  return null;
}
```

### Example 2 — same rule, native-chain style (no shell-ast chain types needed)

```ts
const violations = findCalls(ast)
  .filter((c) => resolvedCmd(c) === "gcc")
  .map((c) => tokenAfter(c, "-o"))
  .filter((o): o is string => typeof o === "string" && !o.startsWith("/tmp/"));
```

### Example 3 — using `flagValues` for batch lookup

```ts
import { findCalls, resolveFlags } from "@questi0nm4rk/shell-ast";

for (const call of findCalls(ast)) {
  const r = resolveFlags(call, { globalFlags: { gcc: ["-o", "-I", "-L"] } });
  if (r?.cmd !== "gcc") continue;
  for (const out of r.flagValues["-o"] ?? []) {
    if (typeof out === "string" && !out.startsWith("/tmp/")) deny();
  }
  for (const inc of r.flagValues["-I"] ?? []) {
    if (typeof inc === "string" && inc.startsWith("/etc/")) warn();
  }
}
```

### Example 4 — pattern not covered by GLOBAL_VALUE_FLAGS

```ts
// dd uses if=/of= syntax (no space, no leading -)
import { findCalls, resolvedCmd, flagsMatching } from "@questi0nm4rk/shell-ast";

for (const call of findCalls(ast)) {
  if (resolvedCmd(call) !== "dd") continue;
  const writeTargets = flagsMatching(call, (f) => f.startsWith("of="))
    .map((f) => f.slice(3));
  if (writeTargets.some((t) => !t.startsWith("./")))
    deny(`dd of= outside workspace: ${writeTargets.join(", ")}`);
}
```

## Locked decisions (signed off 2026-05-16)

1. **`resolveFlags` signature:** optional 2nd `opts` parameter. Stateless. `unwrapCall` threads opts through.
2. **`=` form handling:** shell-ast splits internally. `tokenAfter(call, "--git-dir")` returns the value whether the user wrote `--git-dir /repo` (space) or `--git-dir=/repo` (joined). Rationale: the user is asking "what's the value of `--git-dir`?" — the syntactic form is shell-ast's problem, not the consumer's. Implementation: scan `call.args` for both `flag === "--git-dir"` (literal) and `flag.startsWith("--git-dir=")` (joined); for the latter, return the substring after `=`.
3. **`hasFlag` matching:** broad. Matches literal tokens, combined-short components, and `=`-form LHS. The "give me strict-literal" path is `resolveFlags(call).flags.includes(flag)` if needed.
4. **`flagValues` for repeated flags:** always array. `{ "-c": ["k1=v1", "k2=v2"] }`. Aggregating always; consumer iterates `flagValues[flag] ?? []` for the common single-value case.

### Consequence — singular vs plural query helpers

Decision 4 forces a consistency choice: do query helpers return singular or plural?

- **`tokenAfter(call, flag) → ResolvedArg | undefined`** — first occurrence only. Singular name = singular result. The 99% case.
- **`tokensAfter(call, flag) → ResolvedArg[]`** — all occurrences. Plural name = plural result. Use when you genuinely care about every value (rare; usually `flagValues[flag]` is what you want, but that requires `globalFlags` config).

The earlier `tokensAfter(call, flag, n)` "next N tokens" use case (for `git push origin main` style) is now done via `indexOfFlag` + `tokenAt`:

```ts
const idx = indexOfFlag(call, "push");
const remote = idx !== undefined ? tokenAt(call, idx + 1) : undefined;
const branch = idx !== undefined ? tokenAt(call, idx + 2) : undefined;
```

Slightly more explicit, no `n` parameter to design around.
