# v0.7.0 plan — `unwrapDeep` for chained wrappers (BUG-008 close-out)

**Status:** signoff pending — drafted 2026-05-18 in response to [issue #11](https://github.com/Questi0nM4rk/shell-ast/issues/11).
**Author:** session 2026-05-18.
**Scope philosophy:** shell-ast classifies `bash -c '…'` as `wrapped-script` and auto-recurses via `unwrapCallParsed`'s `innerAst` field. Add `sudo` on the outside and the same logical chain becomes `wrapped(sudo→bash)` — different lens shape, different consumer code path, same security-relevant inner call. The asymmetry IS the pain (hook-kit-Claude on #11, argument 1). v0.7.0 closes that gap with `unwrapDeep` (sync) + `unwrapDeepParsed` (async), returning the chain outermost-first so consumers walk a uniform list regardless of which wrappers compose.

This release closes [BUG-008](../BUGS.md), filed 2026-05-13 and deferred twice (v0.5.0 and v0.6.0). The deferral postmortem produced four lessons now in memory; see "Lessons applied" below.

---

## What this release ships

1. **`unwrapDeep(call, opts?): UnwrappedCall[]`** — sync chain walker. Returns outermost-first. Stops at `plain`, `wrapped-script`, or `wrapped-opaque` (sync can't progress past `wrapped-script` without re-parsing). For `wrapped`, uses 0.6.0's `u.innerRaw` to continue.
2. **`unwrapDeepParsed(call, parse, opts?): Promise<UnwrappedCall[]>`** — async variant. Same logic for `wrapped`, plus: on `wrapped-script` it parses `u.script` and continues walking from the parsed AST's first statement's cmd. The `wrapped-script` layer in the returned chain has `innerAst` populated.
3. **BUGS.md update**: BUG-008 marked FIXED in v0.7.0 with the link to this plan + the cross-references to lessons L2/L3/L4.
4. **IDEOLOGY update**: split "Where each project stops" into "Architecturally rejected" vs "Deferred with revisit-conditions" per lesson L2. Remove `unwrapDeep` from both (it shipped). Add lesson L4 generalization to §11 ("primary lens must be complete"): also covers "lens shape differs across semantically equivalent inputs."
5. **README update**: chain-walking recipe in "Per-command rules" section + v0.7.0 entry in "What's new."
6. **Test additions**: `tests/unwrap-deep.test.ts` (sync), `tests/unwrap-deep-async.test.ts` (async), plus `sudo bash -c '…'` snapshot case in `tests/wrapper-shapes.test.ts` per lesson L4.

## What this release explicitly does NOT ship

- **Cycle detection beyond a runaway-guard.** BUG-008 design says "depth limit lives at the consumer (hook-kit caps at 5)." We respect that: no API-level depth parameter. As a defensive guard against pathological inputs (e.g., `bash -c "bash -c '...'"` nested adversarially), the walker caps internally at **MAX_CHAIN_DEPTH = 100** and returns the partial chain. Consumer caps still apply on the returned array length.
- **A `chain` field on `UnwrappedCall`.** Would either break the discriminated union or duplicate state. Consumers walk the array returned from `unwrapDeep` instead.
- **`unwrapDeep` recursing into `wrapped-script` sync.** Sync stops there because parsing is async-only by construction (`parse()` returns `Promise<ShellFile>`). That's the explicit reason for the two variants.
- **Auto-handling of `wrapped-opaque` next layers.** By definition the inner is unresolvable. Chain terminates.
- **Cross-statement chain branching.** When `wrapped-script.script` parses to multiple statements (`bash -c "rm a; rm b"`), the walker follows only the **first** statement's cmd. Consumers wanting full coverage call `findCalls(u.innerAst)` themselves.

## API: `unwrapDeep` (sync)

```ts
export function unwrapDeep(
  call: CallExprNode,
  opts?: ResolveFlagsOptions
): UnwrappedCall[];
```

**Shape:** array of `UnwrappedCall`, outermost-first. Always non-empty if `unwrapCall(call)` would return non-null (the first element is always `unwrapCall(call)`). May contain up to one `wrapped-script` / `wrapped-opaque` / `plain` (always at the end). All preceding elements are `wrapped`.

**Termination rules:**
- `unwrapCall` returns `null` → push nothing, return `[]`.
- `kind: "wrapped"` → push, continue with `u.innerRaw`.
- `kind: "wrapped-script"` → push, stop (sync can't parse).
- `kind: "wrapped-opaque"` → push, stop.
- `kind: "plain"` → push, stop.
- Depth ≥ MAX_CHAIN_DEPTH → return partial chain. (Runaway guard.)

**Worked example:**

```ts
const ast = await parse("sudo bash -c 'rm -rf /tmp/x'");
const chain = unwrapDeep(findCalls(ast)[0]!);
// chain.length === 2
// chain[0] === { kind: "wrapped", wrapper: "sudo", cmd: "bash", flags: ["-c"], args: ["rm -rf /tmp/x"], flagValues: {}, innerRaw: <synth bash -c>, raw: <outer sudo> }
// chain[1] === { kind: "wrapped-script", wrapper: "bash", script: "rm -rf /tmp/x", flags: ["-c"], args: [], raw: <synth bash -c> }
```

## API: `unwrapDeepParsed` (async)

```ts
export async function unwrapDeepParsed(
  call: CallExprNode,
  parse: (src: string) => Promise<ShellFile>,
  opts?: ResolveFlagsOptions
): Promise<UnwrappedCall[]>;
```

**Shape:** same as sync `unwrapDeep`, but `wrapped-script` layers have `innerAst` populated (via the passed `parse`), AND the walker continues past `wrapped-script` to the inner script's first call.

**Termination rules:**
- All sync rules apply.
- `kind: "wrapped-script"` → push with `innerAst` hydrated. Look at `innerAst.stmts[0].cmd` — if it's a `CallExpr`, continue. If not, or no stmts, stop.
- Parse error on `u.script` → push without `innerAst`, stop.

**Worked example:**

```ts
const ast = await parse("sudo bash -c 'rm -rf /tmp/x'");
const chain = await unwrapDeepParsed(findCalls(ast)[0]!, parse);
// chain.length === 3
// chain[0] === wrapped(sudo→bash)
// chain[1] === wrapped-script(bash, script: "rm -rf /tmp/x", innerAst: <ShellFile>)
// chain[2] === plain(rm, flags: ["-r", "-f"], args: ["/tmp/x"])
```

`parse` is passed in to avoid a circular import (same pattern as 0.6.0's `unwrapCallParsed`).

## Locked decisions

Awaiting sign-off. Lock at signoff with date below.

1. **Two functions, not one.** `unwrapDeep` (sync) and `unwrapDeepParsed` (async). Mirrors the existing `unwrapCall` / `unwrapCallParsed` split. Sync stops at `wrapped-script`; async re-parses.
2. **Chain is outermost-first.** Index 0 is the user-typed call's unwrap; subsequent indices are inner layers. Matches BUG-008 design and hook-kit-Claude's proposal in #11.
3. **No API-level depth parameter.** Consumer caps on returned array length. Defensive `MAX_CHAIN_DEPTH = 100` internal guard against pathological inputs.
4. **Cross-stmt: follow first only.** `bash -c 'rm a; rm b'` → walker follows `rm a`'s cmd, not `rm b`. Consumers wanting full coverage call `findCalls(u.innerAst)` after.
5. **IDEOLOGY refactor: split rejects from deferred.** Per memory lesson L2. `unwrapDeep` exits both lists since it shipped.
6. **§11 generalization.** Per memory lesson L4. "Lens-shape-differs-across-equivalent-inputs" added as sibling to the existing "data-dropped-at-the-boundary" rule.

- **Is minor:** new exports, new doc structure (IDEOLOGY refactor), BUG-008 status changes from deferred to fixed. Feature framing.
