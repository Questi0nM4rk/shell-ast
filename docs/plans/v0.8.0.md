# v0.8.0 — consumer-hardening (Tier 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the genuinely-useful "A-suite" of the v1.0 plan as one coherent consumer-hardening
release — without the public-OSS-launch ceremony — and complete the wrapper/flag *edge-set* so a
future composed command-flow view (Tier 2) has nothing missing underneath it.

**Architecture:** Five independent-ish phases over the existing lens model (no new framework
abstraction): (P1) a `isShellInterpreter` predicate + a `reason` discriminator on `wrapped-opaque`;
(P2) a conservative `GLOBAL_VALUE_FLAGS` expansion for agent-critical tools; (P3) new
command-introducing wrappers (`env`/`timeout`/`nice`/`nohup`) modelled with the *same*
`UnwrappedCall` vocabulary as `sudo`; (P4) a `CAPABILITIES.md` that states the
static-over-approximation contract honestly; (P5) `BUGS.md` reconciliation + a BUG-001
verify-and-mark (not a rewrite — the loader already moved past the doc's proposal).

**Tech Stack:** TypeScript ^6 (strict, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`),
Bun ≥1.3 (`bun:test`), Go ≥1.25 (WASM processor, untouched this release), biome, mvdan/sh v3.

### Why these five and not the rest of v1.0

The v1.0 plan is shaped like a public-OSS-1.0 launch (SBOM, cosign signing, npm provenance,
three-tier stability *machinery*, cross-runtime matrix, published benchmarks, parse-cache,
WASM-size/TinyGo). Per the stack's own Vision, *now→+6mo* is "harden ai-guardrails on the FullStack
repos"; public announce is *+12mo*. So 0.8.0 ships only the items that make shell-ast **better at
its actual job** for its two real consumers (hook-kit, ai-guardrails) and defers the launch ceremony
to whenever an external consumer materialises.

### Locked decisions (2026-06-05 design discussion)

1. **Issue #12 → `isShellInterpreter(name): boolean` predicate**, basename-normalized. NOT exporting
   `WRAPPERS`/`WrapperSchema` (they stay INTERNAL per v1.0 STABILITY). The predicate is derived from
   the registry, so it is auto-complete as interpreters are added — and it is already *more*
   complete than hook-kit's hand-mirrored set (it returns `true` for `runuser -c`, which the
   consumer's hardcoded list misses).
2. **Add the `wrapped-opaque.reason` discriminator now** — `"dynamic-script" | "dynamic-command" | "missing-script"`. This is an observable change to the STABLE `UnwrappedCall` union; landing it here (well before a 1.0 lock) is deliberate.
3. **`GLOBAL_VALUE_FLAGS` expansion is conservative** — only agent-critical tools with stable,
   universal global-flag grammar go ON BY DEFAULT: `aws`, `gcloud`, `terraform`, `npm`, `cargo`,
   `gh`. The volatile long tail (`az`, `helm`, `pnpm`, `yarn`, `bun`, `pip`, `uv`, `glab`, …) stays
   consumer-injectable via the already-shipped `ResolveFlagsOptions.globalFlags`, documented in
   `CAPABILITIES.md`.
4. **Command-introducing wrappers join the SAME vocabulary** — `env`/`timeout`/`nice`/`nohup` become
   `WRAPPERS` entries producing ordinary `UnwrappedCall` shapes (`env rm -rf /` →
   `{ kind: "wrapped", wrapper: "env", cmd: "rm" }`). This completes the wrapper edge-set so a
   Tier-2 command-flow view has every edge.
5. **BUG-001 is verify-and-mark, not rewrite.** `src/wasm.ts` already uses
   `fileURLToPath(import.meta.url)` + `with { type: "file" }` (v0.2.1), guarded by
   `tests/smoke/run-compile-smoke.sh`. The work is to *prove* it holds cross-location and mark the
   bug FIXED with evidence — NOT to apply the BUGS.md `with { type: "wasm" }` proposal over a
   working loader.

## What 0.8.0 explicitly does NOT do

- **Tier 2 command-flow / "execution graph" view.** Its own plan. Reason: largest, least-reversible
  API surface in the project; deserves a dedicated design pass.
- **A literal "what executes" tree.** Architecturally impossible statically (undecidable; command
  resolution is runtime — `$PATH`, function/alias shadowing, `eval`, `$(…)`). shell-ast stays an
  honest static over-approximator.
- **`find … -exec CMD {} \;` / `find -execdir` / `-ok`.** The `{} ;`/`+` terminator parsing is its
  own shape; defer to 0.9.0 with the Tier-2 work.
- **`xargs` inner-command boundary.** The existing known-limitation (BUG-000 §3) stays; `xargs`
  remains in `GLOBAL_VALUE_FLAGS` only. Defer the inner-cmd-as-a-unit treatment.
- **`env -S` / `--split-string` script parsing.** `env -S 'rm -rf /'` carries a whole command in one
  string. Document as a known limitation (it resolves to whatever it resolves to); do not
  special-case the split-string grammar this release.
- **The volatile cloud/pkg tail in the built-in flags default** (decision 3). Consumer-injectable
  only.
- **Any v1.0 ceremony:** SBOM, cosign, provenance, parse-cache, bench suite, cross-runtime matrix,
  WASM-size investigation, `semantic.ts` deprecation dance.

```ts
// Wrapper classification predicates derived from the WRAPPERS registry.
// Keeps the registry itself INTERNAL (per the v1.0 stability tiers) while
// giving consumers a stable boolean lens.

import { WRAPPERS } from "./registry.js";

/** Strip a path prefix to its basename for registry lookup.
 *  `/usr/bin/bash` → `bash`, `./bash` → `bash`, `bash` → `bash`. */
function basename(name: string): string {
  const slash = name.lastIndexOf("/");
  return slash === -1 ? name : name.slice(slash + 1);
}

/** True iff `name` is a shell interpreter — a wrapper that carries its
 *  payload as a *script string* (`bash -c "…"`, `eval "…"`,
 *  `su user -c "…"`, `runuser -c "…"`) rather than as an exec'd argv
 *  (`sudo`, `env`, `exec`, …).
 *
 *  Derived from `WRAPPERS`: a row is a script interpreter iff it sets
 *  `commandFlag` (a `-c`-style script flag) or `commandFromArgs`
 *  (positional script, e.g. `eval`). Adding an interpreter to the
 *  registry auto-updates this predicate — no second list to drift.
 *
 *  Basename-normalized so `/usr/bin/bash` resolves like `bash`.
 *
 *  Consumers (hook-kit SA-02) use this to decide whether a
 *  `wrapped-opaque` layer with a dynamic body must be *escalated*
 *  (shell interpreter → can't inspect the script) vs left alone
 *  (non-shell wrapper). See issue #12. */
export function isShellInterpreter(name: string): boolean {
  const schema = WRAPPERS[basename(name)];
  if (!schema) return false;
  return schema.commandFlag !== undefined || schema.commandFromArgs !== undefined;
}
```

## Phase P4 — `docs/CAPABILITIES.md`

### Task 4.1: Write the static-over-approximation contract

**Files:** Create `docs/CAPABILITIES.md`; Modify `README.md` (link it).

This is a docs task — no failing test, but the worked examples MUST parse against the real API. Each
"cannot see" item gets a runnable snippet.

- [ ] **Step 1: Author `docs/CAPABILITIES.md`** with these sections (content grounded in this
  session's design discussion):

  1. **Status line** + one-line scope (per the docs convention):
     `Status: Reference — what shell-ast can and cannot see.`
  2. **The contract: static over-approximation.** shell-ast runs *before* execution (PreToolUse); it
     reports the commands that *could* run, never a runtime-accurate "what executes" tree. State
     plainly: an accurate execution tree is only obtainable by *running* the command (dynamic
     tracing — `strace -f -e trace=execve`, eBPF `execsnoop`, `bash -x`, `auditd`); statically it is
     undecidable.
  3. **What shell-ast sees:** commands, flags, args (value-flag-resolved via `GLOBAL_VALUE_FLAGS`),
     redirects, pipes, subshells, command substitutions (as opaque shapes), wrappers (unwrapped),
     env-prefix assignments, here-docs, operator effects (`effectOf`).
  4. **What shell-ast CANNOT see** — each with a worked example:
     - Runtime variable values (`$VAR` → `DYNAMIC`).
     - Command-substitution results (`$(get-cmd)` → opaque shape, not the resolved cmd).
     - Aliases (`alias rm='rm -i'` — AST sees `rm`).
     - Function vs binary (`CallExpr` to a user function looks identical to a binary).
     - Conditional reachability (`[ -n "$x" ] && rm` — whether `rm` runs is runtime).
     - `eval`/`-c` of a non-literal (`bash -c "$CMD"` → `wrapped-opaque:dynamic-script`).
  5. **Where wrapper unwrap stops:** the three `wrapped-opaque.reason` values (link the new
     discriminator); `wrapped-script` with non-literal script; chains past a consumer depth cap
     (`unwrapDeep` MAX_CHAIN_DEPTH).
  6. **Wrapper coverage table:** privilege escalators
     (`sudo`/`doas`/`pkexec`/`run0`/`gosu`/`runuser`/`setpriv`/`su`), shell interpreters
     (`bash`/`sh`/`zsh`/`dash`/`ash`/`ksh`/`mksh`/`eval`/`su`/`runuser` — `isShellInterpreter`
     true), command-introducers (`env`/`timeout`/`nice`/`nohup`/`exec` — `isShellInterpreter`
     false). Note the deferred set (`find -exec`, `xargs` inner boundary, `env -S`).
  7. **`GLOBAL_VALUE_FLAGS` coverage + the escape hatch:** the built-in default set (the 6
     original + the 6 new), and how to extend per-call with `ResolveFlagsOptions.globalFlags` for the
     volatile tail. Worked `resolveFlags(call, { globalFlags: { helm: ["--namespace"] } })` example.
  8. **Pairing for ground truth (the 3-ring framing):** static ring = shell-ast (fail toward
     escalation on `dynamic`/`opaque`); runtime ring = a syscall tracer. Complementary, not
     competing.
